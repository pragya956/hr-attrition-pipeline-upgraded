About this project

HR Attrition Analytics — a stratified, leakage-free machine-learning pipeline with categorical encoding, built on the IBM HR Analytics Employee Attrition dataset.

What it does

The app downloads the real dataset with KaggleHub, explores it, trains three classifiers, compares them with stratified cross-validation, evaluates the winner once on a held-out test set and serves predictions through a Flask API.

Pipeline

  1. Split. Stratified 80/20 train/test split (seed 42 by default). The test set is untouched until the end.
  2. Preprocess (inside the pipeline). Numeric: median imputation (+ scaling for logistic regression). Categorical: most-frequent imputation + OneHotEncoder(handle_unknown="ignore").
  3. Cross-validate. StratifiedKFold (5 folds, shuffled, seeded) via cross_validate, so every encoder and imputer is refitted per fold.
  4. Select. The best model is the one with the highest mean CV score on a metric chosen up front (PR-AUC by default).
  5. Test once. The selected model is scored on the held-out set. The test set never influences selection or tuning.

Viva cheat-sheet

Why stratified cross-validation?
Only a minority of employees leave. Stratification keeps that ratio in every fold, so every fold has enough positives and scores are stable.
Where could data leak, and how is it avoided?
Fitting an imputer, scaler or encoder on all rows would let validation data influence training. Here they live inside a scikit-learn Pipeline, so each fold fits them on its own training rows only.
Why not rely on accuracy?
Predicting “stayed” for everyone scores high accuracy but finds no leavers. Recall, F1, balanced accuracy and PR-AUC measure the minority class directly.
How are unseen categories handled?
handle_unknown="ignore" encodes an unseen level as all zeros, so prediction never crashes. The UI shows a warning.
How is class imbalance addressed?
Class weights (balanced) reweight the loss; no resampling is used, so validation and test data are never altered. The decision threshold can be tuned without retraining.
Does feature importance prove causes?
No. It shows statistical association in historical data and can be shared between correlated features.
Excluded columns
EmployeeNumber (identifier), EmployeeCount, Over18, StandardHours (constants), plus any column constant in the training split.

Responsible use

Use this tool for aggregate workforce analysis and decision support. Predictions are probabilities from historical patterns and must not be used for employment, disciplinary or termination decisions about individual employees.
